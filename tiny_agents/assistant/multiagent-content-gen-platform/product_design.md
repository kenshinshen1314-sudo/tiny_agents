## Problem Statement
用户（有分享欲的读书笔记者）积累了大量的阅读素材和收藏内容，但面临"想表达但写不出"的写作障碍。具体表现为：1) 有素材但不知道如何组织成完整文章；2) 担心文章没有内核和逻辑；3) 对长文写作有恐惧感。

## Demand Evidence
用户本人确认的真实痛点：
- 读过很多书，记录了很多优美文字
- 想写公众号但不敢写
- 担心文章没有内核、没有逻辑
- 有强烈的分享欲望

注：目前是个人使用项目，未对外验证。

## Status Quo
用户当前状态：
- 手动收藏/记录好文章和文字
- 使用笔记软件存储素材
- 写作流程：手动组织素材 → 硬着头皮写 → 反复修改
- 痛点：花费大量时间在组织逻辑上，写作效率低

## Target User & Narrowest Wedge
- 用户画像：本人（个人使用）
- 产品阶段：Pre-product
- 最小可行版本：输入素材/想法 → 生成完整公众号文章（markdown格式）
- 核心价值：帮助用户从"有素材但写不出"到"能产出一篇完整的、可发布的文章"

## Constraints
- 先解决个人写作问题，之后考虑扩展
- 输出格式：markdown（可直接发布）
- 支持微信公众号风格
- 技术栈基于现有后端（Python agent服务）

## Premises
1. 用户的核心痛点是"有素材但写不出完整文章" — 同意
2. 期望输出是可直接发布的公众号长文（markdown格式）— 同意
3. 先解决个人写作问题，之后再考虑给其他人用 — 同意

## Approaches Considered
### Approach A: 简单模板填充（Minimal）
- Summary: 用户输入关键词/素材，AI 根据预设模板填充内容
- Effort: S
- Risk: Low
- Pros: 几天上线，简单直接
- Cons: 文章质量依赖模板，可能缺乏深度
- Reuses: 可复用现有后端

### Approach B: 单Agent深度写作（推荐）
- Summary: 强大的写作Agent，理解用户意图后，自主搜索资料、组织逻辑、生成完整文章
- Effort: L
- Risk: Med
- Pros: 一次输入全程自动，能生成有深度有逻辑的长文
- Cons: 需要调优prompt和模型，成本较高
- Reuses: 需全新实现

### Approach C: 多Agent协作流水线
- Summary: 研究规划Agent → 大纲Agent → 初稿Agent → 审核Agent流水线
- Effort: XL
- Risk: High
- Pros: 最符合原始设想，每个环节可独立优化
- Cons: 复杂，调试困难，多Agent通信有延迟
- Reuses: 需全新实现

## Recommended Approach
**Approach B: 单Agent深度写作**

理由：
1. 最快解决核心问题（帮助用户写出文章）
2. 复杂度可控，便于快速迭代
3. 单Agent容易调试和优化
4. 验证成功后可考虑拆分为多Agent

功能范围：
- 输入：用户零散的素材、想法、主题（文本输入，无长度限制）
- 过程：Agent理解意图 → 搜索相关背景资料 → 组织文章逻辑 → 生成初稿
- 输出：完整的公众号文章（markdown格式）

### 实现细节（需确认）
- **搜索工具**: 使用现有后端的 search tool 或 browser tool
- **模型选择**: 基于现有后端配置（可调整 temperature、max_tokens）
- **Prompt 策略**: 需要精心设计的写作 prompt，确保输出有结构、有逻辑
- **错误处理**: Agent 生成失败时的重试机制和用户提示

### 隐藏复杂度
1. 搜索集成需要外部 API 或 browser tool
2. Prompt 调优需要多次迭代
3. 输出质量评估需要人工或规则判断
4. 生成时间可能超过1-2分钟（搜索+生成）

## The Assignment
在现有后端基础上，实现一个单Agent深度写作服务，能够接收用户的素材/想法输入，并生成完整的公众号文章。先做一个最小可行版本上线，验证是否能帮助解决"写不出文章"的问题。
